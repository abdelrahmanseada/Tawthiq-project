# Final report — Tawthiq system with Bremer card identity

## 0. Current state and approach

Latest revision: Tawthiq is the system identity across the website, login, dashboard, verification shell and exports. Bremer is the client company; only its printed card and card preview use Bremer’s logo, name and black/red palette. The earlier platform/multi-company surface remains removed and company data consolidated to one Bremer row.

See `docs/CURRENT-STATE.md` for the pre-change note.

## 1. The idea

HR adds employees and cards; a phone camera scans the QR; `/v/[token]` shows a green verified employee with photo/name/job title or a neutral red/amber invalid state. No login is needed for scanning. Implemented in `app/v/[token]`, `lib/services/verification.ts`, `lib/pdf/card.ts`.

## 2. Identity

- Tawthiq system brand in `lib/brand.ts`, login, shell, verification header and exports.
- Single `Company` row named Bremer; its logo, name and black/red colours are used only by the card/preview.
- New fields: `tagline`, `website`, `logo_bg_dark`, `show_verify_host_on_card` (`prisma/schema.prisma`, migration `20261102090000`).
- `lib/brand.ts`: `PRODUCT_NAME`, `TAGLINE`, `COPYRIGHT_TEXT` via env and `copyrightText()`.
- Bremer card logo upload in settings; dark-background detection in `lib/images.ts`; Tawthiq shield favicon/apple icon generated by `app/api/brand/icon/route.ts`.
- Footer copyright on login, sidebar, verification page and error pages.
- Seed has one owner from env, forced password change and forced 2FA (unless disabled).
- `db:demo` adds 16 fake employees; `db:clear-demo` removes only `DEMO-*`.

## 3. Light theme

`app/globals.css` has only light tokens and `color-scheme: light`; dark mode, toggle and theme cookie removed. `tests/unit/light-theme.test.ts` fails on any `prefers-color-scheme: dark` or `dark:` utility. Verified by 12 Playwright tests including mobile verification and CSV export.

## 4. English/Latin only

`ENABLED_LOCALES=['en']`; Arabic message/shaping/fonts remain dormant and unimported. Latin server validation and import row errors are in `lib/validation/schemas.ts`. `tests/unit/english-purity.test.ts` scans active source, generated PDF and XLSX and rejects Arabic blocks and the words Tawthiq/Facilities. A test scans self-hosted fonts and confirms only Inter.

## 5. Design system

Tawthiq system colours are teal `#0F766E` and amber `#F59E0B`; Bremer card colours are black `#000000` and red `#8F0015`. Surface `#F6F6F7`, white cards, ink `#111111`, border `#E5E7EB`; semantic colors distinct. Muted had to be darkened from the requested `#6B7280` to `#5F6673` because axe measured 4.47:1 on `#F6F6F7` (below WCAG AA). Radii 12/10/999, soft shadows, 8px spacing, lucide icons, Inter self-hosted. Components are the existing `components/ui.tsx` primitives plus CardPreview/PhotoCropper/CardsSelector/ConfirmForm. Responsive/axe tests pass.

## 6. Pages

Login, forced password change, 2FA challenge/enrolment/recovery, shell, dashboard, employees, employee detail/form with photo cropper and live card preview, cards, imports, scan/audit logs, administrators, status, settings, branded 403/404/500. Settings includes identity/tagline/logo/colors/contact/URL/cards/retention and live card+verification previews with unsaved-change guard and per-field errors.

## 7. Card

`lib/card/layout.ts` is the single source used by `lib/pdf/card.ts` and `components/CardPreview.tsx`. Front/back geometry, safe area, colours, website/phone/e-mail/return/tagline, optional verification host, logo plate rules, QR panel/quiet zone and test-print band are implemented. `Card.token_enc` is stored for all new/seed/import cards; PDFs render on demand. Outputs: CR80, print-shop bleed+crop marks, A4 sheet, ZIP. Tests cover 27 layout cases, QR decode in all modes and A4, PDF metadata and token lifecycle. PDF front/back were rendered to `test-output/bremer/page-0.png`/`page-1.png` and reviewed.

Known limitation: the website/verification host may legitimately exceed two lines; the PDF throws a clear render error instead of truncating, preserving the â€œnever truncatedâ€ rule.

## 9. Public URL

`PUBLIC_BASE_URL` / company setting source; QR is `{base}/v/{token}`. Production validation in `lib/qr.ts` rejects HTTP, localhost, `.local`, private/LAN IPs and non-443 ports. Settings has test button (server `/api/health`), LAN helper, persistent warning, card-count warning before change. Front/back host printing is off by default.

## 10. Bugs fixed

1. **CSRF:** `lib/http.ts` accepts only configured APP/AUTH/ALLOWED origins and additionally requires the Origin host to equal the effective Host/X-Forwarded-Host. Test print/ZIP browser actions use fetch/download and show errors.
2. **Time zone:** trim + Intl validation + searchable datalist; settings action now posts `time_zone`.
3. **Colours:** `#RRGGBB` validation, field errors and black/red fallback; action saves the rest even when colours are invalid and returns field errors.
4. **False invalid scans:** internal reasons and a full lifecycle integration test plus QR decode tests.
5. **Docker:** clean `npm ci` in the Docker deps stage and full runner image built; npm pinned 10.9.4.
6. **Chart/photo:** chart has an empty state; no-photo cards show a silhouette and are production-blocked/test-printable.

## 11. Security/2FA

Kept hashed token lookup, AES-256-GCM secrets, CSP nonces, rate limits, RBAC, TOTP + 10 hashed recovery codes, lockout, audit, upload re-encode/EXIF strip, ZIP protections, formula neutralization, retention. Added `REQUIRE_2FA`/`ALLOW_NO_2FA`, 2FA challenge/setup/recovery pages, TOTP attempt rate limiting, `TRUSTED_PROXY=cloudflare` real IP, status warning when 2FA is not required. Production cookies are secure only when APP_URL is HTTPS.

## 13. Data/migrations

Six migrations apply from empty and from the old schema. `20261102130000_single_company_consolidation` moves employees/admins/batches/scans/reports to the oldest (Bremer) company, avoids employee-code collisions and deletes the now-empty extra companies; `20261102140000_consolidate_audit_company` repoints non-FK audit rows; platform audit table and `PLATFORM_ADMIN` enum value are removed. Existing cards retain token hashes/encrypted tokens.
